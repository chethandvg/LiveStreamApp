# HLS Buffer Stall Fix - Complete Summary

## ?? Problem

You were experiencing persistent buffer stall errors:
```
?? Non-fatal HLS error: mediaError bufferNudgeOnStall
?? Non-fatal HLS error: mediaError bufferStalledError
Error: Playback stalling at @219.920086 due to low buffer ({"len": 0.0799130000000479})
```

**Root Cause:** The HLS player was running out of buffer because segments weren't being generated/delivered fast enough to keep up with playback.

---

## ? Solutions Implemented (v2.1)

### 1. Significantly Increased Buffer Capacity

**File:** `Client/wwwroot/js/stream.js`

```javascript
// BEFORE
maxBufferLength: 30
maxMaxBufferLength: 60
maxBufferSize: 60 * 1000 * 1000
maxBufferHole: 0.5

// AFTER
maxBufferLength: 45              // +50% more buffer
maxMaxBufferLength: 90           // +50% more max buffer
maxBufferSize: 120 * 1000 * 1000 // 2x buffer size (120MB)
maxBufferHole: 1.0               // 2x tolerance for gaps
```

**Impact:** Player can now buffer 45-90 seconds of video instead of 30-60 seconds, providing much more cushion against temporary slowdowns.

### 2. Enhanced Nudge Handling

**File:** `Client/wwwroot/js/stream.js`

```javascript
// NEW: Better nudge configuration
nudgeOffset: 0.1,              // Small nudge when stalling
nudgeMaxRetry: 10,             // More nudge retries

// NEW: Separate error tracking
let bufferStalledCount = 0;
let nudgeOnStallCount = 0;
const maxNudgeOnStallErrors = 15;

// NEW: Handle nudge errors specifically
if (data.details === Hls.ErrorDetails.BUFFER_NUDGE_ON_STALL) {
    console.log('HLS.js is automatically handling the stall by nudging playback');
}

// NEW: Manual nudge as backup
if (bufferStalledCount > 5 && video.currentTime > 0) {
    video.currentTime += 0.1;  // Skip forward slightly
}
```

**Impact:** Better handling of playback stalls with both automatic (HLS.js) and manual nudging strategies.

### 3. Optimized FFmpeg for Reliability

**File:** `Server/Shared/StreamProcessor.cs`

```csharp
// BEFORE
arguments.Append("-preset ultrafast ");
arguments.Append("-hls_time 2 ");
arguments.Append("-hls_list_size 10 ");

// AFTER
arguments.Append("-preset veryfast ");        // Better quality/speed balance
arguments.Append("-profile:v baseline ");     // Better compatibility
arguments.Append("-level 3.0 ");              // H.264 level 3.0
arguments.Append("-b:v 2500k ");              // Bitrate control
arguments.Append("-maxrate 3000k ");          // Max bitrate
arguments.Append("-bufsize 6000k ");          // 2x buffer size
arguments.Append("-hls_time 3 ");             // Longer segments (3s)
arguments.Append("-hls_list_size 6 ");        // Smaller playlist
arguments.Append("-hls_init_time 3 ");        // Initial segment duration
```

**Impact:**
- **Longer segments (3s vs 2s):** Fewer segment transitions = fewer opportunities for stalling
- **Bitrate control:** More consistent segment sizes = more predictable buffering
- **veryfast preset:** Better balance between speed and quality
- **Baseline profile:** Better browser compatibility

### 5. Progressive Error Recovery

**File:** `Client/wwwroot/js/stream.js`

```javascript
// NEW: Reduce error counts on successful buffer operations
hlsInstance.on(Hls.Events.BUFFER_APPENDING, function () {
    bufferStalledCount = Math.max(0, bufferStalledCount - 1);
    nudgeOnStallCount = Math.max(0, nudgeOnStallCount - 1);
});

hlsInstance.on(Hls.Events.BUFFER_APPENDED, function (event, data) {
    if (bufferStalledCount > 3 || nudgeOnStallCount > 3) {
        bufferStalledCount = Math.max(0, Math.floor(bufferStalledCount / 2));
        nudgeOnStallCount = Math.max(0, Math.floor(nudgeOnStallCount / 2));
    }
});
```

**Impact:** Error counters decrease when buffering succeeds, rewarding good behavior and reducing false positives.

```javascript

```

If you see different values, **clear browser cache again!**

---

#### 2. **Check FFmpeg is working:**

**Server logs should show:**
```
[INFO] Found FFmpeg at: ffmpeg
[INFO] FFmpeg arguments: ... -preset veryfast ... -hls_time 3 ...
[INFO] FFmpeg process started for stream stream_12345 (PID: 1234)
```

**If FFmpeg errors:**
```powershell
# Check FFmpeg
ffmpeg -version

# Should show version 4.x or higher
```

---

#### 3. **Monitor segment generation rate:**

**If segments are slow (> 5 seconds between uploads):**

**Possible causes:**
- CPU overload (check Task Manager)
- Slow network to Azure (check upload speed)
- FFmpeg struggling (check for warnings in logs)

**Solutions:**
- Reduce broadcaster video quality
- Check server CPU usage
- Verify FFmpeg version
- Check network bandwidth

---

#### 4. **Check viewer download speed:**

**Run in browser console:**
```javascript
const start = Date.now();
fetch('https://your-cdn.azurefd.net/livestreams/your_stream_id/segment_000.ts')

    .then(blob => {

        console.log(`Downloaded ${blob.size} bytes in ${duration.toFixed(2)}s`);
        console.log(`Speed: ${(blob.size / 1024 / duration).toFixed(2)} KB/s`);
    });
```

**Expected:** > 200 KB/s  
**Problem:** < 100 KB/s
